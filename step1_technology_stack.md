# Шаг 1: Выбор технологического стека

## 1. Задача

Выбрать основной веб-фреймворк и библиотеку для построения интерактивных графиков для приложения-бэктестера. Ключевые критерии выбора (согласно `project_plan.md`):

*   **Простота разработки:** Минимум кода, низкий порог входа.
*   **Легкость локального запуска:** Запуск одной-двумя командами.
*   **Интерактивность UI:** Поддержка необходимых виджетов (выбор даты, ввод текста/чисел, кнопки, селекторы) и интерактивных графиков.
*   **Качество визуализации:** Создание наглядных, современных интерактивных графиков.
*   **Python-ориентированность:** Максимальное использование Python, минимум HTML/CSS/JS.
*   **Сообщество/Документация:** Доступность помощи и обучающих материалов.

## 2. Анализ альтернатив

Рассмотрим основные Python-ориентированные варианты:

**А. Веб-фреймворки:**

1.  **Streamlit:**
    *   *Описание:* Фреймворк, специально созданный для быстрого превращения скриптов анализа данных в интерактивные веб-приложения. Пишется на чистом Python.
    *   *Плюсы:* Крайне прост в использовании, очень быстрый старт, отличные встроенные виджеты, хороший механизм кэширования, активное сообщество, легкий запуск (`streamlit run app.py`).
    *   *Минусы:* Модель работы через перезапуск всего скрипта при взаимодействии требует внимания к кэшированию для производительности. Меньше гибкости в кастомизации UI по сравнению с традиционными фреймворками.
2.  **Dash (by Plotly):**
    *   *Описание:* Фреймворк для создания аналитических веб-приложений. Построен на Flask, Plotly.js и React.js, но пишется на Python.
    *   *Плюсы:* Очень мощный для интерактивных дашбордов, нативная интеграция с Plotly, гибкая система колбэков для управления состоянием, большие возможности кастомизации.
    *   *Минусы:* Заметно сложнее Streamlit, требует понимания концепций layout и callback. Запуск чуть сложнее (стандартный Python скрипт).
3.  **Gradio:**
    *   *Описание:* Похож на Streamlit, часто используется для создания демо ML-моделей, но подходит и для других data-приложений.
    *   *Плюсы:* Очень прост для создания интерфейсов с вводом/выводом, легкий запуск.
    *   *Минусы:* Может быть менее гибким для сложных дашборд-лэйаутов по сравнению со Streamlit/Dash. Сообщество и примеры больше сфокусированы на ML.
4.  **Flask/Django:**
    *   *Описание:* Полноценные веб-фреймворки общего назначения.
    *   *Плюсы:* Максимальная гибкость и контроль.
    *   *Минусы:* Требуют написания значительного количества кода для UI (HTML, CSS, JS), маршрутизации и т.д. Явно противоречат требованию максимальной простоты и минимума кода для *данного* проекта.

**Б. Библиотеки визуализации (для интерактивных веб-графиков):**

1.  **Plotly:**
    *   *Описание:* Библиотека для создания интерактивных D3.js / WebGL графиков.
    *   *Плюсы:* Отличная интерактивность (зум, панорамирование, всплывающие подсказки, переключение рядов), множество типов графиков, хорошая интеграция со Streamlit, Dash (нативная), Pandas.
    *   *Минусы:* Может генерировать довольно объемный JS код для сложных графиков.
2.  **Bokeh:**
    *   *Описание:* Альтернатива Plotly для интерактивных веб-визуализаций.
    *   *Плюсы:* Схожие с Plotly возможности интерактивности, может быть чуть легковеснее в некоторых случаях.
    *   *Минусы:* Возможно, чуть менее популярен, чем Plotly, интеграция со Streamlit/Dash возможна, но Plotly часто удобнее.
3.  **Altair:**
    *   *Описание:* Декларативная библиотека статистической визуализации.
    *   *Плюсы:* Элегантный синтаксис для описания графиков, хорошая интеграция с Pandas.
    *   *Минусы:* Интерактивность возможна, но может быть сложнее для реализации кастомных взаимодействий по сравнению с Plotly/Bokeh. Может быть менее подходящим для сложных дашбордов.
4.  **Matplotlib (с интеграцией):**
    *   *Описание:* Стандартная библиотека для статических графиков.
    *   *Плюсы:* Всем знакома.
    *   *Минусы:* Создание *интерактивных* веб-графиков требует дополнительных усилий и интеграции с веб-фреймворком (например, через Flask), результат часто менее плавный, чем у Plotly/Bokeh. Не соответствует требованию интерактивности "из коробки".

## 5. Самокритика и доработка (Шаг 1)

**Оценка выбора стека: 9/10**

**Положительные стороны:**
*   Выбор полностью соответствует основным требованиям проекта: простота, Python-центричность, легкий запуск.
*   Streamlit и Plotly - популярные, хорошо документированные библиотеки с большими сообществами.
*   Комбинация обеспечивает достаточную интерактивность и отличное качество визуализации для задачи.

**Потенциальные риски и области для внимания (почему не 10/10):**
1.  **Производительность Streamlit:** Модель перезапуска скрипта при каждом взаимодействии может привести к задержкам, если не использовать кэширование (`@st.cache_data` для данных, `@st.cache_resource` для объектов типа моделей) для долгих операций (загрузка данных, сложные вычисления). *Это необходимо будет учесть на Шаге 2 (Архитектура) и Шаге 3 (Промпт).* 
2.  **Управление сложным состоянием:** Для *очень* сложных приложений с множеством взаимозависимых виджетов управление состоянием в Streamlit может стать запутанным. *Для нашего приложения это не должно быть серьезной проблемой, но стоит иметь в виду.*
3.  **Гибкость UI:** Streamlit предлагает более ограниченный набор возможностей по тонкой настройке внешнего вида по сравнению с Dash или традиционными фреймворками. *Для нашего проекта функциональность важнее уникального дизайна, поэтому это приемлемый компромисс.*

**План доработки (Шаг 1):**
*   Доработка не требуется, выбор подтверждается. Однако, необходимо явно **зафиксировать требование использовать кэширование Streamlit (`@st.cache_data`, `@st.cache_resource`)** в следующих шагах (Архитектура, Промпт) для оптимизации производительности, особенно для функций загрузки данных и выполнения бэктеста.
